# KorPIX 보안 모델 — 현재 구현과 소버린 AI PC 목표

> 보안 기능의 **설계 목적**과 **현재 프로토타입에 존재하는 통제**는 다릅니다. 본 문서 자체가 보안 인증 또는 법규 준수의 증거는 아닙니다.

## 1. 신뢰 경계 및 정책

| 경계 | 목표 통제 | 현재 상태 |
|---|---|---|
| 단말 | TPM 2.0 키 보호, Secure/Measured Boot, TEE, 단말 신원/원격 증명 | 설계·로드맵 |
| 개인 데이터 | 암호화 금고, 데이터 최소화, 로컬 처리 우선, 키/백업 복구 | 신규 개발 |
| AI/에이전트 | 모델 출력을 실행 권한과 분리, 작업별 정책/위임 검사 | 위험평가·결정 프로토타입 |
| 실행 | 승인 토큰 서명/만료/대상·행동 결합, 재사용 금지, 중단/복구 | Mock Gateway, 미구현 승인 재검증 |
| 데이터 반출 | 수신자·목적·국가·기간·필드별 허용/차단, 동의·철회 | 신규 Egress Gateway 필요 |
| 감사·증거 | 운영용 비대칭 서명, 영구 저장, 해시 재검증, 외부 증명 | 개발용 소프트서명·인메모리 원장 |

## 2. 국민 데이터 주권 원칙

1. 데이터 주체는 누가 어떤 목적으로 데이터를 사용할지, 동의·철회·열람·삭제 요청을 어떻게 행사할지 알 수 있어야 합니다.
2. 로컬 분석을 우선하되, 외부 서비스 이용 시에는 데이터 유형·목적·수신자·지역을 평가하여 최소한만 전송합니다.
3. 국내 인프라 이용은 위험을 줄이는 수단이지 무단 유출을 100% 차단한다는 보증은 아닙니다.
4. 국내·국외 데이터 이전은 관련 법령의 요건을 준수합니다. 모든 해외 전송을 무조건 불법으로 간주하지 않습니다.
5. **국가가 국민의 원본 데이터를 일괄 수집하거나 무단으로 AI 학습에 활용하지 않는 것**을 기본 원칙으로 합니다.
6. 공공·금융 API는 적법한 사업자 지위·동의·공식 기술 명세·기관별 계약/협의를 전제로 합니다.

## 3. 개발용 데이터 위험 분류 예시

기존 UC-004의 1~4등급은 **내부 시연 규칙**이며 법정 개인정보 분류를 대체하지 않습니다.

| 시연 수준 | 예시 | 목표 통제 |
|---|---|---|
| 1 | 일반 프로필 필드 | 목적 검증·최소 수집·정책 충족 시 처리 |
| 2 | 계좌·고유식별정보 등 | 별도 권한/강화된 확인·마스킹·전송 제한 |
| 3 | 건강·복지 등 높은 보호 요구 정보 | 로컬 우선, 별도 법적 근거/동의와 안전성 평가 |
| 4 | 처리 목적과 권한이 없는 정보 | 원칙적으로 거절(DENY) |

단순 SHA-256 해싱만으로 주민번호 같은 식별자의 안전한 익명화가 완성된다고 가정하지 않습니다. 원문 최소 저장, 적절한 키 관리와 가명·익명 처리 검토가 필요합니다.

## 4. 현재 감사 시스템의 제한

- `Audit Gateway`는 형식·소프트 서명·해시·이전 해시를 검증합니다.
- 감사 기록 저장소는 인메모리이며, 재시작 후 영속성을 보장하지 않습니다.
- 소프트 서명은 운영용 전자서명이 아닙니다. TPM 기반 서명은 아직 구현되지 않았습니다.
- 실서비스에서는 저장 데이터 자체의 무결성 재검증, 외부 앵커링/독립 검증, 키 교체·폐기, 백업·복구가 필요합니다.

## 5. 필수 보안 검증 항목 (배포 전 차단 기준)

- [ ] 서명된 정책 허가가 없거나 위조·만료·재사용되면 실행이 실패하는가?
- [ ] 요청한 승인자와 인증된 승인자·위임 범위가 일치하는가?
- [ ] 데이터 반출 차단 정책이 앱 오류·네트워크 우회 상황에서도 강제되는가?
- [ ] 동의 철회 후 추가 전송과 보관 데이터 처리가 정책대로 중단되는가?
- [ ] 비밀값·주민등록번호·계좌 원문이 감사 로그에 불필요하게 남지 않는가?
- [ ] 재시작·장애·백업 복원·키 교체 후 무결성을 검증할 수 있는가?
- [ ] 운영환경에서 Mock 결과나 개발용 서명이 실행·감사 성공으로 보고되지 않는가?

## 6. 기존 투자 서킷 브레이커 예시 (UC-002)

프로토타입의 트리거는 VIX ≥ 35 또는 코스피 일간 하락 ≤ -5%이며 투자 행동의 `DENY`를 시연합니다. **관리자 권한을 독립 검증하는 해제 절차는 추가 개발이 필요**합니다.
